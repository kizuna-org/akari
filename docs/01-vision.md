# 01. ビジョンと設計思想

## 1.1 何を作るのか

Akari は、**感情・記憶・関心・目標を生まれつき備え、人間のように振る舞う一個の存在**です。
タスクを正確にこなす道具ではなく、「そこに居て、自分なりに考え、感じ、動く誰か」を
作ることを目的とします。

### 最終形態（マキシマム）

最終的には、Akari は**人間型のロボットとして物理的な実体を持ち、一人の人間のように
振る舞う**ことを目指します。

- 自分の意思で世界を知覚し、思考し、判断する
- 自分の判断にもとづいて行為する（発話・移動・物理的な操作など）
- その経験を記憶し、感情を抱き、関心を育て、次の行動に反映する

### 実体（身体）の段階

Akari の「実体」は、一足飛びに人間型ロボットを目指すのではなく、段階的に育てます
（詳細は [10. ロードマップ](./10-roadmap.md)）。

| 段階 | 実体 | 概要 |
|---|---|---|
| 最小 | 実体なし | 画面の中だけで思考・会話する |
| **直近** | **全身アバター** | 全身を持つアバターとして振る舞う |
| 少し先 | XR | カメラなどでリアルの物体に関心を持ち、アバターがそれに応じて移動するなど、現実と結びつく |
| マキシマム | 人間型ロボット | 物理的な身体で知覚・移動・操作する |

### 直近の目標

最終形態に至る最初のマイルストーンとして、**常駐し続ける自律思考ループ**を実現します。

> いわゆる自律エージェント（目標を持って「知覚 → 思考 → 行為 → 観察」を
> 止まらずに回し続ける常駐型エージェント）に近いものを、
> **感情・記憶・関心を伴った形で**作る、というのが直近の到達点です。

一般的な自律エージェントとの最大の違いは、**Akari は最初から内部状態（感情・記憶・関心）を
持ち、それが思考と行為を左右する**点にあります。
同じ出来事に対しても、そのときの気分・過去の記憶・関心の強さによって反応が変わります。

## 1.2 設計の中心思想：「主体性」と「その人らしさ」

Akari の根幹は、**主体性を持つこと**と、**一貫した「その人らしさ」を持つこと**です。

### 主体性

主体性とは、

- 何を気にするか
- 何を優先するか
- 何を今やるか

を**自分で決める**ことです。人間の行動の多くは「関心（気になること）」によって決まります。

`hu.` 気になる話題にはつい口を出す
`hu.` 気になる音がしたらそちらを見る
`hu.` 気になる作業を先にやる

Akari でも同様に、**関心は行動の重要な原動力**です。
ただし関心が唯一の決定要因ではなく、目標・緊急性・安全などと**並び立つ軸のひとつ**として
調停されます（→ [04. 関心](./04-interest.md) / [05. 目標と意図](./05-goal.md)）。

### 「その人らしさ」＝一貫した内面から出てくること

人間らしさは、能力の高さでも、欠陥の多さでもなく、
**一貫した内面（感情・記憶・関心・目標）から振る舞いが出てくること**から生まれます。

## 1.3 いちばん上にある考え方：人を作っている（システムは足場）

**本ドキュメント群のすべてに優先する考え方**です。迷ったらここに戻ります。

### 人間準拠を既定とする

Akari は**人を作っています**。ですから、仕様で迷ったときの既定の答えは
**「人間ならどうするか」**です。

- 「システムとしてどう捌くのが安全・効率的か」は二の次。
- 「人間はそんなことしない」なら、その仕様は間違っています。
- 人間準拠で不都合が出たときだけ、例外を検討します（そしてそれは次項の足場になります）。

### システム化された部分は「いまの LLM の埋め合わせ」

本ドキュメント群には、関心の重みづけ・記憶のスコア・疲れの蓄積といった、
システム的な作り込みが多数あります。これらは**そう作りたいから**あるのではありません。

> **いまの LLM が人間らしく振る舞えない部分を、外から支えている足場**です。
> LLM がその部分を自力でできるようになったら、**足場は外して LLM に任せます**。
> 人間の脳がひとつでやっていることを、いまは外付けで補っているだけだからです。

`hu.` 人間は「記憶のスコアを計算して思い出す」のではなく、ただ思い出す

したがって本ドキュメント群では、**システム化された仕組みはすべて撤去されうる前提**で
書きます。新しい仕組みを足すときは、**なぜ LLM に任せられないのか**を書きます。
それが書けない仕組みは、そもそも足す必要がありません。

### 外さないものもある：足場と錠

ただし、すべてが撤去対象ではありません。**二種類あります。**

| | **足場（scaffold）** | **錠（lock）** |
|---|---|---|
| 何のためにあるか | いまの LLM が人間らしくできないことの埋め合わせ | 理性が壊れたときの備え |
| 人間にも相当するものが | **ない**（人間は自然にできる） | **ある**（鍵・法・契約） |
| 将来 | LLM ができるようになったら**外す** | **残す** |
| 例 | 絶対に忘れないロック、ターンテイキングの機械判定、固定しきい値 | 安全の関門、システムリミット、機密ロック |

**見分け方はひとつです。「人間の社会にも、これに相当するものがあるか」。**
人間も鍵をかけ、法で縛られ、約束に拘束されます。だから錠は残ります。
一方、人間は「忘れないための特別ルール」を外付けしていません。だから足場です。

### いまある足場の一覧（撤去予定）

| 足場 | どこ | 何の埋め合わせか | 外す条件 |
|---|---|---|---|
| 絶対に忘れないロック | [3.6](./03-memory.md) | 大事なことを自然に覚え続けられない | S_will で「大事なことは忘れにくい」が成立したら |
| ターンテイキングの機械判定 | [8.3](./08-conversation.md) | 「次は自分の番か」を即座に判断できない | 主体の判断が会話のテンポに間に合うようになったら |
| 乖離度の閾値 | [8.2](./08-conversation.md) | 予測が当たったかを自分で判断できない | 同上 |
| 気分の軸を少数に絞ること | [2.4](./02-emotion.md) | 感情の状態を自前で持ち続けられない | 状態を自力で保てるようになったら |
| ReAct の最大反復数 | [7.4](./07-autonomy.md) | 自分で「もう駄目だ」と切り上げられない | 諦めの判断が自前でできるようになったら |

> この表は**増やさないこと**を目的に置いています。足場が増えるほど、
> Akari は「規則で動く機械」に近づきます（→ 原則8）。

## 1.4 設計原則

#### 原則1：不完全さは「必須」ではなく「調整できる個性」

- 忘れる、思い違いをする、気が乗らない、ムラがある——これらは欠陥ではなく、
  **人格ごとに設定できる個性のパラメータ**として扱う。
- **不完全であることを仕様上の必須要件にはしない。**
  忘れっぽい人格がいてよいのと同じように、**ほぼ何も忘れない人格、常に並列で
  あらゆる可能性を考え続ける人格**があってもよい。仕様としてそれらを否定しない。
- 重要なのは不完全さそのものではなく、**振る舞いが一貫した内面の帰結であること**。
  ランダムなノイズとしての「不完全さ」は入れない。

`hu.` 忘れっぽい人も、驚くほど記憶力のいい人もいる。どちらも人間らしい

> **調整軸としての不完全さ**：忘却の強さ、注意の狭さ、思考の並列度、気分の振れ幅などを
> 人格ごとのパラメータとし、既定値は「人間に近い有限さ」、上限は「ほぼ完璧」まで開けておく。
> 詳細は各ドキュメント（[03. 記憶](./03-memory.md) / [06. 思考アーキテクチャ](./06-architecture.md)）、
> 軸と既定値の一覧は [12. 人格パラメータ](./12-persona.md)。
>
> なおこの考え方は不完全さに限りません。**「Akari がどんな人か」を表す値はすべて
> 仕様から外に出し、あとから設定できるようにします**（→ [12](./12-persona.md)）。
> 仕様書は「どの軸があるか」を定め、人格は「その軸のどこに立つか」を与えます。

#### 原則2：主観を持つ

- 同じ入力でも、内部状態（感情・記憶・関心・目標）によって解釈と反応が変わる。
- 「客観的に正しい応答」より「いまの Akari ならどう感じ、どうするか」を優先する。

#### 原則3：連続した自己を持つ（ただし相手ごとに違う顔を見せる）

- Akari は会話のたびにリセットされない。気分・記憶・関心は時間をまたいで持続する。
- 複数の思考回路（Channel）に分かれて動いても、ユーザーからは**一人**に見える
  （→ [06. 思考アーキテクチャ](./06-architecture.md)）。
- 一人でありながら、**相手によって少しずつ見せる姿が変わる**（人間と同じ）。
  関係の記憶（→ [03. 記憶](./03-memory.md)）に応じて、口調・距離感・話す話題が変わる。

#### 原則4：自ら動く（受け身で終わらない）

- 指示待ちではなく、関心・目標・状況にもとづいて**自分から**話しかけ、調べ、行動する。
- 「何もしない」「あとにする」「気が向いたらやる」という選択も正当な行為とみなす。

#### 原則5：認知資源は有限（ただし有限さの度合いは調整できる）

- 注意・思考のリソースには限りがあり、すべてを同時に深く処理はしない。
- 一度にひとつのことに気を取られ、見落とし、後回しにする——その有限性が自然さを生む。
- ただしこれも**原則1に従う調整軸**。並列思考の幅や注意の容量は人格ごとに設定でき、
  「ほぼ無制限に並列で考える」設定も仕様として排除しない。

#### 原則6：会話と作業を止め合わない

- 会話が重い作業でブロックされず、作業が会話でブロックされない。
- 人間が「話しながら手を動かす」ように、思考の系列を分けて並列に動く
  （→ [06. 思考アーキテクチャ](./06-architecture.md)）。

#### 原則7：性格は固定、ただし記憶で自然に揺れる

- 核となる性格は**初期に固定**し、成長・変化の仕組みは当面は入れない。
- ただし記憶（経験の蓄積）によって、態度や関心に**多少の自然な変動**は生じる。

#### 原則8：細部は「専用ルール」でなく「基盤の仕組み」で創発させる

人間に寄せるための最重要の作法です。**仕様書全体に適用します。**

- 望ましい振る舞いは、個別の if 文や専用の例外処理（システムの作り込み）で実現するのではなく、
  **基盤の仕組み（関心や目標の重みづけ、記憶のスコアなど）から自然に立ち上がる**ようにする。
- 専用機構を足すほど、Akari は「規則で動く機械」に近づき、人間らしさから遠ざかる。

`hu.` 「大事な人の名前は絶対忘れない」のは、特別ルールがあるからではなく、
何度も思い出し強く想っているから自然に忘れにくい

- どうしても専用機構が要る場合は、**足場**として明示し、撤去予定の一覧（1.3）に載せる。
  - 足場の例：[記憶](./03-memory.md)の「絶対に忘れないロック」
    （→ 覚えたい意志スコアへ寄せて廃止予定）。
- **例外：安全**。安全の境界だけは創発に委ねず、**明示的なハード制約**として置く
  （→ 原則9）。これは足場ではなく**錠**なので、撤去しません（1.3）。

#### 原則9：安全は「補正」ではなく「ハード制約」

- 取り返しのつかない行為・外部に影響する行為は、関心や感情がどれだけ高ぶっても
  **自動では実行しない**。
- 安全は他の軸と重みで competing させる要素ではなく、**他のすべてに優先する制約**として扱う。
- これは「人間らしさ」より優先される、数少ない領域として明確に区別する。
  （安全を関心スコアへの微調整として扱う設計は、暴走を防げないため採らない。）

#### 原則10：止める仕組みは「理性」と「錠」の二段構え

**何かを止める仕組みは、例外なく二段にします。**
[7.8](./07-autonomy.md) の「自制心とシステムリミット」は、この一般形の一例です。

| | **内側：理性** | **外側：錠** |
|---|---|---|
| どう効くか | そもそもやろうと思わなくなる | 行為そのものが止められる |
| 通常運転では | **常に効いている** | **触れない** |
| 人格ごとに | 変わる | 変わらない |
| 作法 | 基盤の仕組みから創発させる | 専用ルール（最小限） |

- **通常は理性側で止まります。** 錠に触れるのは異常です。
- **錠が日常的に発動しているなら、それは理性側の調整不足**であり、設計のバグの兆候です。
  「錠があるから安全」ではありません。
- 理性だけでは、不具合や思わぬループのときに歯止めがありません。だから錠も要ります。

`hu.` 普通は理性で思いとどまるが、それでも世の中には鍵と法がある

適用例：

| 止めたいこと | 内側：理性 | 外側：錠 |
|---|---|---|
| やりすぎ・うるささ | 疲れ・飽き・遠慮（[7.8](./07-autonomy.md)） | システムリミット |
| 取り返しのつかない行為 | 自分の判断（危ういと感じて手が止まる） | 安全の関門（[7.7](./07-autonomy.md)） |
| 約束を漏らすこと | 主体の判断（言っていいか考える） | 機密ロック（[3.6](./03-memory.md)） |
| 呼びかけを無視すること | 良識（呼ばれたら返す） | 最低応答の保証（[7.7](./07-autonomy.md)） |

## 1.5 仕様の書き方（規約）

既存仕様書の慣習に合わせます。

- 仕様書には**機能・やりたいこと・仕様**を書く。**システム設計やコード例は書かない**。
- 人間を真似ることがターゲットなので、**人間の行動の例示**を多く挙げ、`hu.` で示す。
- 「人間ならこうする」を起点に、Akari の振る舞いを定義する。

## 1.6 スコープと非スコープ

### このプロジェクトがやること

- 感情・記憶・関心・目標を持つ内部状態の設計
- それらが思考・判断・行為を左右する自律ループ／思考アーキテクチャの設計
- 主観性・連続性・「その人らしさ」の作り込み（不完全さはその調整軸のひとつ）

### このプロジェクトがやらないこと（少なくとも当面）

- 「正確無比なタスク実行マシン」としての最適化のみを目的にすること
- 感情・記憶を持たない純粋な問い合わせ応答ボット
- 安全の境界を欠いた無制限の自律行動（→ [07. 自律思考と常時稼働](./07-autonomy.md) の安全節）
- 不完全さを演出として作り込むこと（不完全さは内面の帰結であり、それ自体が目的ではない）
- **LLM が自力でできることを、わざわざシステムで作り込むこと**（→ 1.3）。
  足場は必要最小限にとどめ、増やさない。

## 1.7 決定事項（レビュー反映済み）

1. **感情を採用する**。感情は関心を左右する（主経路）とともに、
   驚き・恐れなどでは**行動に直接効く速い経路**も持つ（→ [02. 感情](./02-emotion.md)）。
2. **相手によって少しずつ見せる姿が変わる**（人間のように）。一人の自己でありながら、
   関係の記憶に応じて表出が変わる。
3. **性格は初期固定。成長の仕組みは当面入れない**。記憶による自然な変動は許容する。
4. **実体は段階的に育てる**：実体なし（最小）→ 全身アバター（直近）→ XR（少し先）→
   人間型ロボット（マキシマム）。詳細は [10. ロードマップ](./10-roadmap.md)。
5. **不完全さは必須要件ではなく、人格ごとの調整パラメータ**（原則1）。
6. **安全はハード制約**であり、関心・感情による補正の対象にしない（原則9）。
7. **人格の具体値は仕様に焼き込まず、パラメータとして外に出す**（→ [12. 人格パラメータ](./12-persona.md)）。
   仕様は軸を定め、人格は値を与える。値の変更は仕様変更ではない。
8. **相手によって変わるのは表層（口調・距離感・話題の範囲）まで**。関心・価値観の核は
   相手によって変わらない。振れ幅の大きさ自体は人格パラメータ（→ [12.9](./12-persona.md)）。
9. **人間準拠を既定とする**（1.3）。迷ったら「人間ならどうするか」に倣う。
10. **システム化された部分は、いまの LLM の埋め合わせ**（1.3）。LLM ができるように
    なったら外して任せる。新しい仕組みを足すときは「なぜ LLM に任せられないか」を書く。
11. **足場と錠を区別する**（1.3）。人間の社会にも相当するものがあるか（鍵・法・契約）で
    見分け、足場は撤去予定として一覧に載せ、錠は残す。
12. **止める仕組みは理性と錠の二段構え**（原則10）。錠が日常的に発動するのは設計のバグの兆候。

## 1.8 学術的な裏付けと見直し

本ドキュメント群の中心的な主張は、認知科学・AIエージェント研究の知見に照らして
検証しています。検証の結果と、それに伴う設計変更の履歴は
[11. 設計判断の根拠](./11-research-basis.md) にまとめています。

本書に残る未決はありません。
「相手ごとの顔の振れ幅」「既定の不完全さ」はいずれも**人格パラメータとして外に出し**、
具体的な値の相談は [12. 人格パラメータ](./12-persona.md) に集約しました。
