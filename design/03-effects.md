# 03. 行為と MCP の境界

## どのChannelが道具を使うか

思考と一体の情報取得は、その情報を必要とするChannelが行います。
返答中の資料参照はInteraction、仮説を確かめる検索はSpeculationでも行えます。
独立した手順・進捗・中断再開が必要な仕事はActionの系列へ引き受けさせます。
MCPサーバーやツールごとにChannelを作りません。

全Channelは共通のAction Gatewayを通し、MCP / CLI / HTTPの生クライアントを持ちません。
実行アダプターは認証とプロトコル変換を担当し、行為の可否を独自に決めません。
自発発話と媒体への送信も同じ行為の境界に入ります。

## 行為の契約

行為要求には、呼び出し元、実行・相関ID、actual / predictionの実行文脈、
対象・受け手・引数、根拠となる意図や判断、期待する作用、機密範囲を含めます。
実際の実行文脈はruntimeが与え、モデルが `actual` を自己申告して昇格できないようにします。

登録側は道具の性質を定義します。MCPの readOnly / idempotent 等のannotationは参考情報であり、
安全の証明にはしません。ツール名が `get` でも実際の情報送信先や副作用を調べます。
未知の道具は利用可能な道具集合に入れず、登録と作用の確認後に有効にします。

| 性質 | 判断するもの |
|---|---|
| 作用 | 読む・戻せる更新・戻せない更新・発話など、実際に何が変わるか |
| 受け手 | いまの場、受け取る用意がある相手、その場にいない相手 |
| 送信情報 | 道具の入力に何が含まれ、どの信頼境界へ出るか |
| 競合 | 同じファイル・会話・対象など、同時実行で整合が崩れる範囲 |
| 再試行 | 重複実行できるか、外部の冪等キーを使えるか |

## 理性と錠

通常はChannelが危うさ・遠慮・疲れを踏まえて、実行しないことも選びます。
Gatewayは、その判断に失敗した場合でも実際の作用を止める錠です。
読むだけ・戻せる行為・受け取る用意のある相手への発話は、自分の判断で行えます。
その場にいない受け手や取り返しのつかない作用には確認を挟みます。
グループの同席者は全員に受け取る用意があるという確定仕様を維持します。

確認が必要な行為はpendingに戻し、mindや他Channelを待たせません。
承認は対象・引数・受け手・機密範囲・行為IDに結び付けます。
別の行為への使い回し、承認後に対象が変わった実行、モデル自身の承認は認めません。
承認待ちは同時実行workerの枠を占有しません。

機密ロックは想起を止めず、外へ出す行為に効かせます。
機密性は同席者への発話でも検査し、検索語や引用・要約・作業名にも引き継ぎます。
外部検索は読み取りであっても、検索語を外部へ送信する行為です。
単純な禁止語の一致では要約による漏洩を止められないため、出所・共有合意の範囲を保持し、
必要なアクセス分離と出力確認を組み合わせます。完全に検出できるとは主張しません。

## 予測は実行の権限を持たない

predictionは読み取り可能な道具だけを要求でき、外界や長期記憶の更新は実行できません。
ここでの読み取りは、機密範囲・送信情報の検査も通ったものに限ります。
安全な読み取りとして登録された道具には、通常のアクセスログ等の付随的記録がありえます。
予測による業務上の更新や外部通知がないことを確認し、確認できない道具は予測では使いません。

予測結果は別の一時領域に保持し、実際の経験として記憶へ書き込みません。
予測が当たった後も、新しいactualの判断で再検証します。
predictionから承認トークンや外部更新の実行権限を引き継ぎません。

## コミットと実行

新しい意図・矛盾を解く必要のある行為・取り返しのつかない作用は意識のコミットを通します。
思考中の参照や、コミット済みの仕事の範囲内の手順は、共通境界を通して並列に実行できます。
すべての検索を意識に一回ずつ上げる設計にはしません。
同じ対象の更新はGateway側で順序づけ、競合しない読み取りは並列にできます。
ロック順を一定にし、LLM待ちや承認待ちの間は対象ロックを保持しません。

実行前に作用・機密・承認・対象版を再確認し、実行を記録してから呼び出します。
外部送信後のtimeoutは「失敗」ではなく結果不明です。無条件で再試行しません。
外部の冪等キーまたは照合APIがあれば復旧し、なければ状態を報告して確認へ回します。
CLIの子プロセスも取消・timeoutで回収し、SDKの自動retryが錠を迂回しないようにします。
