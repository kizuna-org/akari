# 05. 実装の進め方と検証

## 先に固定しないもの

感情マイルストーンの配置と振る舞いの具体的な合格条件、最初の媒体、利用するモデル、
接続する道具・アクセス先は後で決めます。透明性の方針も検討中です。
基礎設計では、これらの具体値に依存しない境界・所有・実行順を定義しました。
未決の項目を理由に、心理的な専用ルールや暫定の固定人格を増やしません。

## 実装順

| 段階 | 作るもの | 検証すること |
|---|---|---|
| 0（実装済み） | Goのホスト、Makefile、Docker、CI、基礎設計、合意済み仕様の反映 | 起動・bind失敗・health・終了、build / lint / race / coverage |
| 1（基礎部分実装済み） | snapshot / proposal / commitment、mindの単一所有、Channel生命周期 | 二つの思考が重なり、片方が止まっても他方が進む。取消後の結果を採用しない |
| 2（状態基盤実装済み） | 人格と4つの内面、体験文脈の形成、記憶ポート | 人格値が主体に漏れない。気分・意図が会話をまたぐ。関心に忌避を表せる |
| 3（基礎部分実装済み） | 行為のGateway、錠、予測分離、承認待ち | すべてのChannelが同じ境界を通る。未知の道具・確認が必要な無承認の行為を実行しない |
| 4（保存・回復の基礎実装済み） | 保存・outbox、回復、状態の投影、管理用観察 | 未保存の更新を実行しない。結果不明の送信を重複しない。外部状態に機密が出ない |
| 5 | 選定したLLMと媒体・道具を実接続 | 内面を伴う対話・自律行動の一連の振る舞い。細かい合格条件はレビューで決定 |

これはコードの依存順であり、人格のロードマップではありません。
本番の一連の振る舞いは感情・記憶・関心・目標を備えた段階から始めます。
LLMのないfake Channelで並列性を検証しても、自律思考が完成したとは扱いません。

## このブランチで動く契約

- `mind.Workspace` は短い排他区間で共有文脈を更新します。snapshotとproposalをコピーし、
  宣言された読み取り・書き込み対象の版を照合します。通知は最新版への合流で、遅い購読者を待ちません。
- `thought.Supervisor` は系列ごとの世代・取消・完了の受取・採用を扱います。
  実行中と未解決の完了を合わせて上限を設け、取消だけで枠を再利用しません。
  実際の選択判断は持たず、渡されたrunnerを独立して実行します。
- `action.Gateway` は登録アダプターを共通境界に置きます。Channelに渡すSessionは承認機能を持たず、
  runtimeが与えた宛先の範囲を検査します。predictionはReadだけ、戻せる行為は自分の判断、
  不可逆の行為と受け取り準備のない相手への発話は外部承認を要求します。
  承認は変更できない一つのPendingに結び付けます。
- 行為は同じ競合対象なら直列、異なる対象なら容量内で並列に進みます。
  adapter呼び出し前の取消はNotExecuted、呼び出し後のerror / panicはUnknownです。
  同じPendingを二度実行できません。これはプロセス内の保証で、永続的な重複防止ではありません。
- パニックを起こしたrunner / adapterを失敗として返し、他の系列を巻き込みません。
  取消を無視するrunnerをGoで強制終了はできないため、Closeは呼び出し側の期限で戻ります。
  同じSupervisorで停止待ちを繰り返しても待機goroutineを増やしません。

Workspaceの容量は共有文脈のキー数、SupervisorとGatewayの容量は実行資源の上限です。
人格の意識の広さや記憶の寿命ではありません。購読は終了時に解除し、runnerは取消に協力する契約です。

## 未接続・未完成の部分

文字列の共有文脈に加え、人格を固定した内面・意図・意味座標を載せました。
想起・モデル解釈・保存のポートと、採用・取消・予測拒否の振る舞いは [07](./07-inner-state.md) にあります。
型ごとの常設Channel、意識による選択、呼びかけの予約容量、最低応答、媒体への状態投影も後続です。
Scopeは宛先の許可範囲をコピーする基礎的な能力制限です。
既知の会話の出所と機密合意は内面からGatewayへ接続し、実行前にも確認します。
生成・要約・検索語への完全な出所の追跡、出力確認、対象版の再検証は未実装です。
predictionは外部変更と、実際の内面・長期記憶へのコミットの両方を拒否します。

実MCP、CLI、媒体は登録していません。ローカルの保存・復元・outboxは [08](./08-durable-state.md) にあります。
思考の採用と行為を一つに保存し、承認を記録し、クラッシュ後の結果不明を再送せず照合するポートを備えます。
実サービスの冪等性と照合、承認の時間による失効、管理画面とホストの起動・終了への配線は後続です。
現在のModelポートは体験全体の参照版をruntime側で記録します。
より狭い体験を渡す場合の依存追跡は後続で実装します。
現在のversion照合だけで意味の矛盾や虚偽の依存宣言を検出できるとは扱いません。

## 必須の実行検証

テストはtable-drivenとし、状態を共有しないケースには `t.Parallel()` を使います。
時刻・乱数・モデル・道具は消費側から差し替えられるようにし、sleepで順序を祈るテストにしません。
開始・完了の同期点で順序を作り、race detectorも使います。

基礎部分の検証を継続し、後続では未接続の条件も含めます。

- 遅いActionがあってもInteractionが候補を返せる。着想があふれても呼びかけが扱われる。
- snapshotのmap / sliceを変更しても共有状態が変わらない。
- 古い世代、変更された依存対象、重複イベントを適切に扱う。
- 配信から遅れたChannelが採用済みの意図と状態を再取得する。
- 同じ対象への更新を直列化し、異なる対象の仕事は同時に進む。
- predictionから外部更新・長期記憶更新をできない。
- 承認後の引数変更、別行為への承認流用、秘密を含む検索語を拒否する。
- 外部成功後のtimeout、保存失敗、復旧中のクラッシュで重複送信しない。
- 最低応答と本返答が競合しても二重送信しない。
- 停止でworker / 子プロセス / listenerを回収する。

internalパッケージのカバレッジは約100%を維持し、薄いプロセス入口は実バイナリで確認します。
成功するfakeだけで達成したことにせず、
重要な不変条件・障害時の挙動・実際の起動経路を確認します。

## 足場の検証と撤去

LLMに任せたい判断はChannel側の実装へ寄せ、状態保持やスコアの足場と境界を分けます。
モデル変更後も同じ振る舞いの観察例を使い、外せる足場を評価します。
錠の発動回数は成功指標にせず、正常な理性で止まれなかった原因の観察に使います。
コスト・遅延・トークン量と、人としての疲れ・飽きは別に測ります。
