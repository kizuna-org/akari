このディレクトリは Go / Docker を維持して組み直した技術設計です。
振る舞いの仕様は [docs](../docs/README.md)、技術上の境界と実装契約はこちらに置きます。
仕様の確定事項を優先し、設計上の選択を人格や振る舞いの新しい仕様として扱いません。

## このブランチの範囲

基礎設計と、DBやLLMの資格情報なしで起動・停止・検証できる最小のホストを用意しました。
`internal/mind` の共有状態、`internal/thought` の並列実行、`internal/action` の共通境界も
実装し、疑似の思考系列と道具を組み合わせて検証しています。
人格を固定した四つの内面も共有状態へ接続し、疑似モデルによる提案の採用・取消・予測分離を検証しました。
ローカル保存・復元・outboxも実装し、思考の採用と保存、クラッシュ後の再送拒否を検証しました。
ホストはまだこれらを起動せず、Akari の思考ループではありません。
具体的な常設Channel、実LLM、MCP、ホストへの保存・復元の配線、管理画面は後続で接続します。
health が成功しても人格の稼働を意味しません。

基礎実装と本番用の契約の差は [実装順](./05-delivery.md) に明記します。

Go 1.26.2、GoLand のプロジェクト、Docker Compose を維持します。
旧 ORM / DI / RPC、別モジュールの Kiseki、Terraform、自動デプロイ、DB必須の起動経路は
新しい基礎から取り除きます。旧コードは元ブランチとGit履歴に残ります。
新しい保存方式やプロバイダーを採る場合は、必要になる段階で理由を明記します。

## 会話で合意したこと

| 項目 | 決定 |
|---|---|
| Q-01 | 外部には反応がない理由が分かる状態を伝え、Channelなどの詳細は管理画面へ |
| Q-02 | 能力章は当面維持し、仕様を探しにくくなった時点で分割 |
| Q-03 | 会話の間は08章、場は09章。相互参照する |
| Q-04 | 内面を伴った対話 → 自律的行動 → 記憶の深化 → 会話・作業の自然さ |
| Q-05 | 感情は初期から備え、独立したマイルストーンで達成を確認 |
| Q-06 | 達成条件は振る舞い。管理コンソールは横断的な開発支援 |
| MCP | 情報取得は必要とするChannelが行う。独立した継続作業はActionが引き受け、外部アクセスの境界は共通に置く |

感情マイルストーンの配置・具体的な達成条件、初期媒体、LLMと接続先は未決です。
透明性の方針は引き続き検討中です。これらを暫定設定で確定したことにはしません。

## 足場と錠

新しい心理的な専用ルールは足しません。候補の選択、記憶のスコア、気分の保持など、
既存の足場には「何を補うか」「外す条件」を [01-vision](../docs/01-vision.md) に従って持たせます。
goroutine管理・状態の排他・クラッシュ回復は実行基盤の責務です。
人格の制御とは区別し、LLMの向上だけでデータ競合や外部APIの障害がなくなるとは考えません。
安全の関門、システムリミット、機密ロック、最低応答の保証は錠として残します。
