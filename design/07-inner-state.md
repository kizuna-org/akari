# 07. 内面状態と共有状態の接続

この実装は [感情](../docs/02-emotion.md)、[Kiseki](../docs/03-memory.md)、
[関心](../docs/04-interest.md)、[目標と意図](../docs/05-goal.md)、
[人格](../docs/12-persona.md) の確定仕様に沿った状態の基盤です。
自然な対話や感情マイルストーンの達成を、このテストだけで宣言しません。

## 所有と反映

`mind.NewWithInner` が一つの人格をコピーして固定し、共有文脈と四つの内面を所有します。
`Snapshot.Experience` は体験側のコピーです。人格の設定ベクトルや、記憶の全履歴は入りません。
短期のcontext / working memory、気分・感じていること・行動準備、関心、願い・意図、疲れ、
機密合意を思考の材料にします。

`Proposal.Inner` は未採用の更新です。各柱の参照版を示し、既存の共有文脈への差分と一緒に、
一度の短いコミットで検証・反映します。どこかの検証に失敗すると、気分だけ変わるような部分反映はしません。
参照していない柱の更新だけで提案を捨てず、変更された前提に依存する結果は拒否します。
意味の整合をモデルに再検討させる責務はChannel側です。

更新の上限は二種類あります。意図数・意識の広さは確定済みの人格軸です。
`Settings.Contents` は保持する内容の個数に対するホスト資源の制限で、人格による記憶の寿命ではありません。

## 人格

`persona.Config` は仕様書の34軸を順序の固定された一本のベクトルとして持ちます。
schema 1、連続軸は0〜1、個数軸は正の整数、記憶の五つの重みは配分として検証します。
既定値、好き・嫌いな領域、感情の偏りの記述は12章をそのまま維持します。

思考側に設定表の読み取り能力を渡しません。数値は内面の更新に効き、その結果である体験を渡します。
設定やチェックポイントの読み取りは管理・保存側の能力です。
「振る舞いから自分の傾向を推し量る」ことを禁止する設計ではありません。

実装済みの数値の効き先は、反応性・共感・地の気分・引きずりやすさ、記憶の重み、
意図数・意識の広さ、疲れやすさ・回復です。
好みの種や感情の偏りの文章は保持していますが、まだ実際の意味空間へ符号化していません。
表出・慣れ・移ろいやすさなどの残る軸も、今回の状態基盤だけで実装済みとは扱いません。

## 感情と関心

感情や行動準備は自由な文章・意味ベクトル・連続的な強さで持ち、閉じた感情の列挙は置きません。
Appraisalは主体側の解釈で、複数の感情、相手から受けた感情、行動準備、気分の三軸への寄与を含みます。
反応性・共感を反映した感情と、直接経路の行動準備を別々に残します。
行動準備があるだけでは、外部操作の権限は得られません。

気分は快・高ぶり・近づく向きの三軸を積み重ね、経過時間で基準点へ戻ります。
感情・行動準備は別の時間単位で薄れます。新しいappraisalは、その時点の感情のまとまりを返します。
不快な状態もそのまま持ち、表出度が低いことを「感じていない」へ置き換えません。

関心は意味空間上の対象と符号を持つ親和度です。無関心と忌避を区別します。
`interest.Salience` は意味の近さ・気分・疲れから、関心の一入力を作ります。
正の気分で関わりやすくなり、疲れで全体への関わりが弱くなります。
これを行動選択の唯一の点数にはせず、意図・緊急性・会話責務・安全と競わせる選択器は後続です。
進展・新奇さ・飽き・関心の核の扱いは、主体側の解釈と後続の実装に残します。

これらの計算は、仕様にある足場の可逆的な実装です。
時間単位は`Settings`から与え、今回のテストで使う1時間を本番の心理的な定数にしません。
減衰曲線や関心への数値の効かせ方は、実際のモデルを使った振る舞いの観察で調整します。
状態を主体が保持できるようになったときは、同じ観察例で足場を外せるか評価します。

## 記憶と意図

Kisekiはcontext / working memoryとday / sleepingの記憶を区別します。
`memory.Reader` は手がかりに沿った想起だけを返します。
意味・人気・鮮度・感情・覚えたい意志の五つを人格の配分で合わせ、強さも反映します。
想起した内容はworking memoryへ戻せ、working memoryを空にしても長期側は消しません。
想起そのものは読み取りで、実際に採用した想起の参照回数は別のコミットで増やします。
感情と記憶を同時に採用すると、その時点で実際に感じた強さを記憶の感情スコアへ反映します。

`memory.Consolidator` は主体側の圧縮・忘却・再構成をつなぐためのポートです。
Sleep実装、忘却のムラ、重要な約束の暫定保護はまだ接続していません。
ランダムな誤記憶や、時間だけで重要な記憶を消す処理は追加しません。

願いは複数保持でき、互いに矛盾していてもよい状態です。
意図は主体が明示的に採用・終了し、関心の更新だけでは消しません。
手順の位置と保留状態を残し、再開時に何をしていたかを受け取れます。
同じ正規化済みの対象に異なる要求を持つ意図は拒否し、保留中の意図も引き受けた数へ含めます。
この要求の照合は構造的な検査です。任意の文章の意味的な矛盾をすべて見抜く仕組みではありません。

疲れは感情から分け、採用した意識内容の量で増え、明示的な休息で戻ります。
`thought.Mode.ConsciousLoad` はruntimeが与えます。モデルの返り値にはこの値や人格変更の欄がありません。
同じモデル呼び出しでも潜在意識として処理する内容は0、意識に上げる内容はその量を指定します。
未採用・取消・予測・検証失敗の結果で疲れを増やしません。

## LLM・MCP・保存への接続

| ポート・境界 | 渡すものと責務 |
|---|---|
| `meaning.Encoder` | 文章から意味空間の版と座標を作る。プロバイダーは未選定 |
| `thought.Model` | 体験と選ばれた想起を受け、内面の解釈を返す。人格・負荷・実行権限を決めない |
| `thought.FromModel` | 全体の体験を読んだ依存版をruntime側で記録し、返り値を未採用の提案へ変換 |
| `memory.Reader` | 思考のための想起。記憶の全履歴や管理ログの出口にしない |
| `action.Prepare` / `Session` | MCP等を信頼されたアダプターで正規化し、共通の宛先・作用・承認・機密境界へ通す |
| `mind.Checkpoint` / `continuity.Repository` | 人格の固定設定と版、体験、記憶とoutboxを保存する管理側の契約。[08](./08-durable-state.md)で実装 |

異なるencoderの空間は同じ次元数でも比較しません。
LLMの返した任意の座標・機密の自己申告をそのまま信頼する、本番のアダプターは作りません。
解釈の読み取り対象を狭める場合は、渡す体験も狭め、実際に読んだ対象をruntime側で記録します。
現行のModelは体験全体を読むため、四つの柱と疲れの全参照版を依存にします。

予測はruntimeが印を付け、`mind.Commit` が実際の共有状態への反映を拒否します。
Gatewayの読み取り専用Sessionと組み合わせ、予測を実経験や長期記憶の更新へ昇格させません。

記憶は会話の出所を保ち、機密合意は会話のまとまりに付けます。
アダプターの`Operation.Sources`をコピーし、`Scope.Disclosure`へ現在の合意を照会します。
準備時だけでなく実行枠の取得後も確認し、合意が変わった行為をNotExecutedとして止めます。
出所があるのに確認するポリシーがない場合も拒否します。想起は許可し続けます。
未知の出所・言い換え・生成内容の漏洩検査、受け手集合の正規化は引き続きアダプター側との接続が必要です。

外部LLMへ体験・検索語・記憶を送る場合も、送信情報の機密範囲と認証の境界を決めてから接続します。
このブランチでは実モデル・MCPサーバー・秘密情報・有料サービスを使いません。
ローカル保存・復元・outboxによる原子性・人格照合・結果不明の照合ポートは [08](./08-durable-state.md) にあります。
実サービスの照合とホストへの配線は、外部更新を本番接続する前に実装します。

ホストは引き続き生存確認だけです。具体的な常設Channel、入力媒体、最低応答、
選択・自律行動ループは実接続していません。
