# 02. 並列思考と共有状態

## 並列に考え、短い処理で反映する

mindが状態の唯一の書き手です。各Channelにはコピーされた不変のsnapshotを渡します。
slice・map・ポインタを浅くコピーして共有せず、snapshotの境界で所有を切ります。
Channelは状態差分や行為候補を返し、mindが採用して次版を配ります。

一回の状態反映は短く、LLM・道具・保存先の長い応答を待ちません。
I/Oは別のworkerで行い、完了・失敗・期限切れをイベントとして戻します。
LLMを呼ぶ仕事を一つのtickで全部待つ実装、全Channelへの同期的な一斉配信は採りません。

## 最小の実装契約

| 値 | 必要な情報 |
|---|---|
| Event | ID、発生元、対象となる場・相手、観測時刻、相関ID、内容と機密範囲 |
| Snapshot | 状態版、採用済みの共有内容、気分・関心・意図・作業記憶、必要な関係文脈 |
| Proposal | ID、ChannelIDと世代、参照版、評価根拠、依存対象の版、候補や状態差分 |
| Commitment | 意図ID、採用版、実行主体、行為の範囲、同時実行時の競合対象 |
| Observation | 実行ID、成否・不明、観測結果、実際の作用、出所と機密範囲 |

ID・版は一貫性のための実行情報です。内面の意味的距離を文字列ラベルへ置き換えません。
候補の評価には関心・目標・緊急性・会話責務・中断コストが関わり、安全はその上位の制約です。
固定の重みや疲れの換算式はこの段階で新しく確定しません。

## 共有の順序

1. 入力を受け、重複を識別し、対象に関係するChannelへ通知する。
2. Channelはsnapshotを受けて独立に考え、候補を返す。
3. mindは候補を保持し、前面に上げるものを選ぶ。
4. 選ばれた内容を共有する。全Channelが最後に受け取った採用版を把握できるようにする。
5. 統合が必要ならChannel側に再考を依頼する。mindの中で長時間待たない。
6. 整合した提案を意図としてコミットし、自己の流れへ記録する。
7. 行為の実行結果を観察として受け、記憶・気分・関心へ反映する。

意識層の広さが複数でも、状態のコミット順は一つにします。
一度に扱う内容を複数にすることと、矛盾した状態更新を同時に確定することは別です。
願いは矛盾でき、引き受けた意図は整合しなければなりません。

## 古い結果と中断

ProposalにはChannelの世代と、読んだ対象の版を付けます。
取消済み世代からの結果は採用しません。関係する意図・会話・機密範囲が変わっていれば再評価します。
全体の版が進んだだけで常に捨てると長い仕事が永久に採用できないため、
依存対象が変わっていない結果は採用可能です。意味の整合が不明なら主体側で再考します。

中断は `context` の取消と、作業候補のpausedへの遷移を分けます。
取消したgoroutineが終わらないまま同じ仕事を再開しません。
終わった仕事は解放し、保留中の意図・要点・再開位置はmind側へ戻します。
候補の保持は人格の粘りと文脈に従い、固定TTLで忘れさせません。
実行上のタイムアウトやキュー上限は別の設定です。

## 詰まりを会話へ波及させない

入力と完了のmailboxは有界にします。会話の呼びかけには予約容量を持たせ、
バックグラウンドの着想で全容量を占有しないようにします。
単なる状態通知は最新版へ合流できますが、呼びかけ・コミット・行為の結果は黙って捨てません。
配信が遅れたChannelは前回の配信版から追いつくか、最新snapshotを取り直します。

最低応答の監視は遅いモデル呼び出しと別に走らせます。
通常はInteractionの良識で返し、期限に届いたときだけ「あとで」等を返す錠を使います。
対象の呼びかけIDと応答済み状態を確認し、期限ぎりぎりの本返答と二重送信しません。
具体的な下限時間は人格で変更できない運用設定とし、値は後で決めます。

疲れは意識に採用した内容の量から蓄積させます。
モデルのトークン数・HTTP回数・経過時間をそのまま疲れと同一視しません。
慣れた手順は意識の負担を減らせますが、行為の錠を回避する権限は得ません。

## 異常の扱い

モデルや道具の障害は失敗イベントとして取り込み、別のChannelは継続します。
状態の破損、保存不能、goroutineの回収不能では処理を無制限に続けず、
外部更新を止めて状態を知らせ、修復できなければプロセスを失敗終了させます。
「止まらない」は通常の常駐と一時的障害からの復帰を指し、壊れた状態で作用を続ける意味ではありません。
